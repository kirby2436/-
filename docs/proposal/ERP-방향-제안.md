# 1. 요약

- ERP를 메뉴 중심이 아니라 **현장 한 건이 영업 → 설계 → 공사관리 → 생산 → 청구로 흘러가는 흐름** 중심으로 만든다.
- 회사 양식과 자료를 분석한 결과, 가장 큰 문제는 **같은 숫자를 여러 파일에 옮겨 적는 것**이다. 부재 한 건의 면적이 설계 BOM → 출고 실적 엑셀 → 거래명세서 → 납품수량 증빙 → 납품대금 청구서로 4~5번 옮겨진다.
- 그래서 다음에 만들 것(2차)은 **출하 등록과 거래명세서 자동 출력**으로 정했다. 출하 실적이 차량·부재 단위로 쌓여야 그다음의 청구서를 자동으로 만들 수 있다.
- 주력 제품은 보데크(네오빔)와 데크(네오데크) 둘이다. **보데크를 먼저 만들고 데크를 나중에 붙인다.** 다만 두 제품이 함께 쓰는 부분(프로젝트, 거래처, 계약, 청구, 수주현황)은 처음부터 제품 구분을 넣어 만든다.
- 구글 캘린더는 없애지 않고, ERP에 입력한 일정이 구글 캘린더에 자동으로 표시되게 한다.
- 회계는 마지막에 다룬다.

1판과 달라진 점: 2차 범위가 "입고 달력"에서 "출하·거래명세서"로 바뀌었고, 청구서를 기성 방식으로 고쳤으며, 경영 현황(수주·매출 예측) 영역이 추가되었다.

# 3. 회사 자료 분석 결과

분석 대상은 현장 폴더 견본 1건, 실제 현장 폴더 1건, 한 달 치 거래명세서, 출고 실적관리 엑셀, 납품대금 청구서 1회분, 경영 현황 엑셀 7종이다. 이 문서에는 항목 구조만 적고 실제 거래처명, 인명, 금액은 적지 않는다.

## 3.1 현장 폴더

- 폴더명은 `프로젝트코드 현장명(원청_계약사)` 형식이다.
- 하위 폴더는 수취도면, 영업, 설계, 공사 넷이고, 부서 폴더명 뒤에 담당자 이름을 붙인다.
- 수취도면은 `수취일 + 수단(내용)` 폴더로 차수를 구분한다.
- 버전은 파일명 끝의 날짜로만 구분하고, 구버전은 `이전`, `휴지통` 같은 폴더를 직접 만들어 옮긴다.
- 폴더명 앞의 기호(★ 등)로 진행 상태를 표시하는 규칙이 있으나 실제로는 지켜지지 않는다.

## 3.4 확인된 문제

1. **부재 정보의 연쇄 수작업**: BOM → 출고 실적 엑셀 → 거래명세서 → 납품수량 증빙 → 청구서.
2. **파일명에 손으로 적는 합계**: 거래명세서 파일명에 차량 대수, 부재 수, 면적을 적는데 내용과 어긋난 파일이 있다.
3. **현장 정보의 중복 입력**: 같은 계약의 금액과 물량이 경영 엑셀 3종에 따로 입력되어 값이 서로 다르다.
4. **견적 개정 혼선**: 개정 차수를 파일명 날짜로만 구분해, 같은 이름의 파일이 서로 다른 금액으로 존재한다.
5. **이전 파일 복사로 인한 잔재**: 수주보고서 시트와 증빙자료에 다른 현장의 값이 남아 있다.
6. **깨진 수식**: 집계 시트 여러 곳에 참조 오류가 있고, 요약표의 총계가 시트마다 다르다.
7. **표기 불일치**: 제작장, 차종, 운송회사, 결제조건, 지역이 자유 입력이라 같은 대상이 여러 이름으로 적힌다.
8. **기록 부재**: 현장 폴더에 입고 일정표, AS 기록, 현장 사진이 없다.

# 4. 설계 방향

## 4.1 현장 한 건의 흐름

| 단계 | 담당 | ERP에서 일어나는 일 |
|---|---|---|
| 견적 접수 | 영업 | 견적 대장에 등록 |
| 도면 수취 | 영업 | 수취 차수별로 도면 등록 |
| 물량 산출 | 설계 | 영업의 설계 의뢰가 설계의 할 일로 생성, 산출 결과 등록 |
| 견적 제출 | 영업 | 산출 물량과 단가표로 견적서와 영업실행예산 작성, 개정 이력 보관 |
| 계약·수주 | 영업 | 계약 등록, 수주보고서 작성과 결재, 프로젝트 생성 |
| 실시 설계 | 설계 | 구간별 SHOP·BOM 등록(1차 버전 기능) |
| 입고 협의 | 공사관리 | 현장개요 등록, 출하 예정 등록 |
| 생산·출하 | 생산 | 차량별 상차 편성, 거래명세서 출력, 출고 실적 누적 |
| 청구·수금 | 공사관리 | 마감 기간의 출하 실적으로 기성 청구서와 증빙 작성, 수금 기록 |
| 정산 | 영업 | 정산보고서 |

## 4.2 원칙

1. **한 번만 입력**: 부재, 거래처, 현장, 단가는 한 번 입력하고 뒤 단계 문서에 다시 쓴다.
2. **회사 양식 그대로 출력**: 지금 쓰는 양식 모양으로 엑셀이나 PDF를 내보낸다.
3. **합계는 시스템이 계산**: 차량 대수, 부재 수, 면적, 기성 금액을 사람이 적지 않는다.
4. **자유 입력 대신 목록 선택**: 제작장, 차종, 운송회사, 결제조건, 지역, 견적 상태.
5. **부서별 첫 화면과 할 일**: 설계 의뢰, 출하 예정처럼 부서 간 요청을 기록으로 남긴다.
6. **현장에서 휴대폰으로**: 일정 확인, 방문 기록, AS 접수.
7. **작게 만들어 바로 쓴다**: 한 번에 한 부서의 한 가지 업무.
8. **두 제품 공통 구조**: 공통 자료에는 제품 구분(보데크, 데크, 보데크+데크)을 둔다.

# 5. 제안 기능

## 5.1 출하와 거래명세서 (2차)

| 기능 | 내용 |
|---|---|
| 현장개요 | 주소와 진입 안내, 하차 담당자, 진입 가능 차량, 코너철판 유무를 현장에 한 번 등록 |
| 기준정보 | 제작장(위치와 운영 주체 구분), 운송회사, 차종 |
| 차량별 상차 편성 | 구간 BOM의 미출고 부재를 골라 차량에 배정. 면적은 회사 규칙으로 자동 계산 |
| 거래명세서 출력 | 회사 양식으로 차량별 출력. 공급번호 자동 부여, 대수·부재 수·면적 자동 합계 |
| 출하 예정 | 날짜가 정해진 출하를 "예정"으로 등록해 목록으로 조회. 달력과 구글 캘린더 표시의 바탕 자료 |
| 출고 실적 | 부재별 접수일·생산일·제작장·출고일. 현장별·제작장별·월별 집계, 미출고 부재 조회 |
| 진행현황 연동 | 구간의 부재가 모두 출하되면 출고 단계 실적 자동 반영 |

## 5.2 납품대금 청구 (3차)

| 기능 | 내용 |
|---|---|
| 계약 내역 | 품목별 단위, 수량, 단가. 자재 단가는 보 폭·높이 구간별. 계약 수량 없이 실투입으로 정산하는 품목 구분 |
| 마감 기간 | 현장별 마감일(25일 또는 말일)에 따라 그 기간 출하분을 금회 기성으로 집계 |
| 단가 구간 자동 판정 | 출하 부재의 폭과 높이로 단가 구간을 찾아 면적을 구간별로 합산 |
| 기성 청구서 | 표지와 청구내역서를 회사 양식으로 출력. 전회·금회·누계와 기성률 자동 계산, 단수조정 |
| 증빙 자동 생성 | 월별 집계표, 일자별·차량별 납품수량, 거래명세서 묶음 |
| 스터럽 입고와 청구 | 입고일, 구간, 톤수를 기록하고 청구 회차를 표시. 미청구분은 다음 청구서에 자동 포함 |
| 추가 청구와 공문 | 부재 삭제·변경으로 생긴 비용을 계산 근거와 함께 등록, 공문 출력 |
| 수금과 미수금 | 결제조건으로 입금 예정일 계산, 청구 대비 수금 기록 |

## 5.8 데크(네오데크)

보데크 기능이 자리 잡은 뒤 붙인다. 견적 대장, 수주현황, 계약, 청구서 틀은 공통으로 쓰고, 물량 산출과 출하 단위는 데크 양식을 받은 뒤 따로 설계한다. 필요한 자료는 데크의 견적서, 거래명세서, 청구서 한 벌씩이다.

# 7. 구글 캘린더 처리 방안

1판과 같다. ERP가 원본이고 구글 캘린더에는 자동으로 표시한다(양방향 동기화는 하지 않는다). 2차에서 만드는 "출하 예정"이 캘린더로 올라갈 자료다. 캘린더 표시는 실제 일정 표기 예시를 받은 뒤 붙인다.

# 8. 개발 순서

| 순서 | 범위 | 이유 |
|---|---|---|
| 완료 | 프로젝트·구간, BOM 업로드, 진행현황 | |
| 2차 | 현장개요, 기준정보, 출하 등록, 거래명세서 출력, 출고 실적 | 중복 입력이 가장 심한 부분. 청구 자동화의 바탕 |
| 3차 | 계약 내역, 기성 청구서와 증빙, 스터럽 입고, 추가 청구, 수금 | 출하 실적이 있어야 가능 |
| 4차 | 견적 대장, 설계 의뢰, 견적서와 영업실행예산, 수주보고서 결재 | 영업 업무를 ERP 안으로 |
| 5차 | 수주현황, 영업 목표, 납품계획 대비 예상 매출 | 계약과 출하 자료가 쌓인 뒤 가능 |
| 6차 | 입고 달력과 구글 캘린더 표시, AS, 현장 방문 | 캘린더 표기 예시 필요 |
| 7차 | 데크(네오데크) | 데크 양식 필요 |
| 8차 | 회계 연계 | 본사와 협의 후 결정 |

# 9. 확인이 필요한 사항

1. **제작장 목록**: 사내와 외주, 공장 안의 외주 제작장 구분. (정리해서 받기로 함)
2. **프로젝트 코드 규칙**: 제품 문자와 끝의 분류 문자의 뜻. (설명을 받기로 함)
3. **결재선**: 수주보고서를 누가 검토하고 누가 승인하는지.
4. **면적 계산의 올림 단위**: 부재 1개의 면적을 올림한 뒤 수량을 곱하는지, 수량을 곱한 뒤 올림하는지.
5. **공급번호 규칙**: 날짜별 일련번호가 차량마다 올라가는지, 출하 건마다 올라가는지.
6. **거래명세서 양식**: 제작장별로 다른 3가지 양식을 하나로 통일해도 되는지.
7. **캘린더 일정의 실제 표기** 예시.
8. **회사 서버**: 현장 폴더를 ERP로 옮길지, 서버를 그대로 두고 경로만 연결할지.
9. **설치 위치**: 현장에서 휴대폰으로 쓰려면 인터넷에서 접속되는 서버가 필요하다.
