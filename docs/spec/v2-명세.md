# NEOTEC ENC 건설자재 ERP — 2차 버전 명세

출하 등록과 거래명세서 자동 출력을 만든다. 배경은 `docs/proposal/ERP-방향-제안.md` 3장과 5.1절 참고. 기본 구현은 10장의 가정대로 끝났다(2026-11-23). 10장의 미결 사항이 정해지면 해당 부분을 고친다.

## 1. 목표

지금은 부재 정보를 BOM에서 출고 실적 엑셀로, 다시 거래명세서로 옮겨 적고 합계를 파일명에 손으로 적는다. 2차가 끝나면 1차에서 올린 구간 BOM에서 부재를 골라 차량에 배정하는 것만으로 거래명세서가 출력되고 출고 실적이 쌓인다.

## 2. 범위

포함:
1. 기준정보: 제작장, 운송회사, 차종
2. 현장개요
3. BOM 부재의 면적과 보 구분 자동 계산
4. 출하 등록(예정 → 출하 → 취소)과 차량별 상차 편성
5. 거래명세서 출력(인쇄 화면, 엑셀)
6. 출고 실적 조회, 미출고 부재 조회
7. 구간 출고 단계 실적 자동 반영, 홈에 출하 예정 표시

제외(3차 이후): 금액과 청구서, 스터럽 입고, 생산일과 생산 실적, 달력과 구글 캘린더 표시, 과거 출고 실적 엑셀 이관, 데크.

별도 진행: 프로젝트 코드 체계 변경은 코드 규칙 설명을 받은 뒤 작은 태스크로 따로 한다(10장 2번).

## 3. 설계 원칙

1차 명세 2장의 원칙을 그대로 따른다. 추가:

- 합계(차량 대수, 부재 수, 면적)는 화면과 출력물에서 항상 시스템이 계산한다. 사람이 입력하는 칸을 두지 않는다.
- 제작장, 운송회사, 차종은 목록에서 고른다. 목록에 없으면 그 자리에서 추가한다.
- 출하된 수량은 BOM 수량을 넘을 수 없다.
- 출하를 지우지 않는다. 잘못된 출하는 "취소" 상태로 바꾸고 기록을 남긴다.

## 4. 디렉터리와 소유권

```
erp/
  core/        모델, 마이그레이션, 서비스(area, shipping)   (T1 소유)
  shipping/    기준정보, 출하, 거래명세서, 출고 실적 화면    (T3, T4, T5 소유. 파일 단위로 나눔)
  projects/    현장개요 구역 추가                            (T2 소유)
  bom/         면적·보 구분 열 표시, 업로드 시 계산 호출     (T2 소유)
  schedule/    홈에 출하 예정 추가                           (T5 소유)
```

규칙은 1차와 같다. 모델과 마이그레이션은 `core`에만 두고, 다른 태스크는 `core`를 수정하지 않는다.

## 6. 공통 서비스 (`core/services/`, T1 구현)

### 6.1 `area.py`

- `parse_profile(text)` → `(bottom, side1, side2)` 또는 `None`.
  - `NB400X450`, `DH400X450`: 하판 400, 측판 450 두 장.
  - `NBL400X450`, `DHL400X450`: 하판 400, 측판 450 한 장(`side2` = 0).
  - `400/450/420`처럼 숫자 셋: 하판, 측판1, 측판2.
  - 대소문자, 공백, `x`/`X`/`*`를 구분하지 않는다. 해석할 수 없으면 `None`.
- `unit_area(bottom, side1, side2, length_mm)`: `(하판 + 측판1 + 측판2) × 길이 ÷ 1,000,000`을 **소수 둘째 자리에서 올림**. 예: 폭 합계 1,300, 길이 5,640 → 7.332 → 7.34.
- `line_area(unit_area, quantity)`: `unit_area × quantity`. (10장 4번이 정해지면 바뀔 수 있다. 계산을 이 함수 한 곳에만 둔다.)
- `member_kind(ass_mark)`: 부재 부호로 BEAM/GIRDER 판정. 규칙은 10장 5번 확인 후 확정. 판정할 수 없으면 빈 값.
- `fill_bom_item(bom_item)`: 위 값들을 채운다. BOM 업로드 저장 때와 Profile·길이 수정 때 호출.
- 관리 명령 `recalc_bom_area`: 기존 BOM 전체를 다시 계산.

### 6.2 `shipping.py`

- `remaining_qty(bom_item)`.
- `next_supply_no(ship_date)`: `NEO-YYYY-MM-DD-NN`. NN은 그 날짜의 2자리 일련번호(10장 6번).
- `confirm(shipment, user)`: 예정 → 출하. 검증(차량 1대 이상, 차량마다 부재 1건 이상, 수량이 남은 수량 이하, 면적이 계산된 부재만), 공급번호 부여, `area` 보관, 구간 상태 갱신, 감사 기록.
- `cancel(shipment, user, reason)`: 취소. 구간 상태 갱신, 감사 기록. 공급번호는 재사용하지 않는다.
- `sync_section_shipping(section)`: 구간의 모든 BOM 부재가 출하되었으면 `is_completed = True`, `confirmed_ship_date` = 마지막 출하일. 아니면 `is_completed = False`. 그 뒤 1차의 `schedule.sync_section_activities`가 출고 단계 실적을 맞춘다. BOM이 없는 구간은 건드리지 않는다.

## 7. 화면 명세

### 7.1 기준정보 (T3, `shipping/`)

- 제작장, 운송회사, 차종 각각의 목록과 추가·수정 화면. 삭제 대신 "사용 안 함".
- 제작장 목록은 위치별로 묶어 보여주고 자사/외주를 문구로 표시한다.

### 7.2 현장개요와 BOM 표시 (T2, `projects/`, `bom/`)

- 프로젝트 상세에 "현장개요" 구역과 수정 화면 추가. 진입 가능 차량은 차종 체크 상자.
- 구간 편집에 제작장 선택 추가.
- 구간 BOM 표에 폭(하판/측판1/측판2), 면적, 보 구분, 출하 수량/남은 수량 열 추가. 면적을 계산하지 못한 행은 "규격 확인 필요"로 표시하고 그 자리에서 폭을 직접 입력할 수 있다.
- BOM 합계에 총 면적 표시.

### 7.3 출하 (T3, `shipping/`)

- **목록** `shipping:list`: 필터(기간, 프로젝트, 제작장, 상태). 열: 출하일, 프로젝트, 구간, 제작장, 차량 대수, 부재 수, 면적, 상태. 한 줄 제목은 지금 파일명과 같은 순서(날짜, 현장, 층·구간, N대, M부재, 면적, 제작장)로 자동 구성. 휴대폰에서는 카드형.
- **등록** `shipping:create`: 프로젝트, 출하일, 도착일, 제작장, 출하 담당 입력. 제작장 기본값은 구간의 제작장.
- **상차 편성** `shipping:load`:
  - 왼쪽(휴대폰에서는 위): 프로젝트의 미출고 부재. 구간으로 거르고 Ass Mark로 검색. 열: 구간, Ass Mark, Profile, 길이, 남은 수량, 면적.
  - 부재를 여러 개 골라 "N호차에 담기". 수량은 남은 수량이 기본값이고 줄일 수 있다(나눠 싣기).
  - 오른쪽(아래): 차량별 담긴 부재와 소계(부재 수, 면적). 차량 추가, 부재 빼기, 다른 차량으로 옮기기.
  - 여러 구간의 부재를 한 출하에 담을 수 있다.
  - 현장개요의 진입 가능 차량에 없는 차종을 고르면 경고만 표시.
- **상세** `shipping:detail`: 읽기 전용. 차량별 운송 정보(운송회사, 차종, 차량번호, 기사, 연락처)와 부재 목록. 예정 상태에서만 "수정", "출하 확정". 출하 상태에서는 운송 정보만 수정 가능하고 "취소"(사유 입력, 확인 단계)가 있다.
- 규칙: 출하 확정과 취소는 확인 단계를 거치고 AuditLog에 남긴다.

### 7.4 거래명세서 (T4, `shipping/`)

- **인쇄 화면** `shipping:statement`: 차량 1대당 A4 1장. 한 출하의 모든 차량을 이어서 인쇄하거나 차량 하나만 인쇄.
  - 머리: 공급번호, 공급자(회사 정보는 설정값), 공급받는자(매출처, 현장명, 현장 주소, 하차 담당자), 출하일, 현장 도착일, 출하 담당, 운송회사, 차종, 차량번호, 기사, 연락처, 층·구간.
  - 부재 목록 열: no, DWG.NO(Ass Mark), 규격, 하판, 측판1, 측판2, 길이, 수량, 면적(㎡), 위치(BEAM/GIRDER), Location. 끝에 "이하여백".
  - 합계: 수량, 면적.
  - 금액 칸은 없다.
  - 부재가 한 장에 들어가지 않으면 다음 장으로 넘기고 쪽 번호를 표시한다.
- **엑셀 내보내기** `shipping:statement_xlsx`: 같은 내용을 차량당 시트 1개로. 파일명은 지금 규칙과 같게 자동 생성.
- 회사 양식 원본과 나란히 놓고 칸 위치와 문구를 맞춘다(10장 7번에 따라 양식 1종).

### 7.5 출고 실적 (T5, `shipping/`, `schedule/`)

- **출고 실적** `shipping:performance`: 기간 필터. 집계 축 선택(월별, 프로젝트별, 제작장별). 값: 차량 대수, 부재 수, 면적. 출하 상태만 집계한다.
- **부재별 내역** `shipping:lines`: 필터(기간, 프로젝트, 구간, 제작장). 열: 프로젝트, 층·구간, Ass Mark, Profile, 길이, 수량, 면적, 보 구분, Location, BOM 등록일, 제작장, 출고일, 공급번호. 엑셀 내보내기.
- **미출고 부재** `shipping:unshipped`: 프로젝트·구간별 남은 수량과 면적. 구간의 출고예정일이 지난 것을 먼저 보여준다.
- **홈**: "이번 주 출하 예정"을 예정 상태의 출하 기준으로 바꾸고, 예정 출하가 없는 구간은 1차와 같이 구간 출고예정일로 표시.

## 8. 품질 기준

1차 명세 7장과 같다. 추가:

- 면적 계산은 실제 거래명세서에서 확인한 값으로 단위 테스트를 둔다(규격과 길이만 쓰고 현장명은 쓰지 않는다).
- 남은 수량을 넘는 출하, 취소 뒤 수량 복원, 나눠 싣기, 여러 구간 묶음 출하, 구간 완료 자동 반영과 해제를 테스트한다.
- 거래명세서 인쇄 화면은 A4 인쇄 미리보기로 확인하고, 다른 화면은 PC 폭과 360px 폭에서 확인한다.

## 10. 미결 사항

| 번호 | 내용 | 정해지기 전의 가정 |
|---|---|---|
| 1 | 제작장 목록(사내, 외주, 공장 안의 외주) | 모델만 만들고 목록은 비워 둔다 |
| 2 | 프로젝트 코드 규칙(제품 문자, 끝의 분류 문자) | 1차의 자동 코드를 유지한다 |
| 3 | 수주보고서 결재선 | 2차 범위가 아님 |
| 4 | 수량이 2 이상일 때 면적 올림 순서 | 부재 1개 면적을 올림한 뒤 수량을 곱한다 |
| 5 | BEAM/GIRDER 판정 규칙 | 자동 판정하지 않고 비워 둔다. 수동 선택 가능 |
| 6 | 공급번호 일련번호가 차량마다 올라가는지, 출하 건마다 올라가는지 | 차량마다 올라간다 |
| 7 | 거래명세서 양식을 하나로 통일해도 되는지 | 가장 많이 쓰는 양식 하나로 만든다 |
| 8 | 출하 담당을 사람마다 로그인 계정으로 둘지, 글자로 적을지 | 글자로 적고 최근 값을 기본값으로 쓴다 |

## 11. 구현하면서 정한 것

담당자 확인 없이 구현 중에 정한 동작이다. 실무와 다르면 고친다.

| 항목 | 동작 |
|---|---|
| BOM 교체 등록 | 출하(예정, 취소 포함)에 담긴 부재가 있는 구간은 "새로 등록"을 할 수 없고 "추가 등록"만 된다. 출하에 담긴 BOM 행은 삭제할 수 없다 |
| 남은 수량 | BOM 수량에서 예정과 출하 상태의 상차 수량을 뺀 값. 취소는 빼지 않는다 |
| 구간 완료 | 출하 상태의 수량만으로 판정한다. 모든 부재가 출하되면 완료, 취소로 모자라게 되면 완료가 풀린다. 출고확정일은 지우지 않는다 |
| 취소 | 예정과 출하 상태 모두에서 가능하고 사유가 필수다. 취소된 차량의 공급번호는 다시 쓰지 않는다 |
| 공급번호 | `NEO-YYYY-MM-DD-NN`, 차량마다 올라가고 100대를 넘으면 세 자리가 된다 |
| 거래명세서 | 표준 양식 1종. 한 장에 부재 31행, 넘으면 다음 장. 출하일 칸을 추가했고 출하 담당 연락처 칸은 없다. 예정 상태는 "출하 확정 전 미리보기"로 표시된다 |
| 거래명세서 버튼 | 출하 상태에서만 보인다 |
| 출고 실적 | 출하 상태만 집계한다. 제작장은 출하에 지정한 제작장 기준이다 |
| 미출고 부재 | 완료·강제완료 프로젝트는 제외한다 |
| 상차 편성 | 미출고 부재는 한 번에 500건까지 보여준다. 부재가 담긴 차량은 삭제할 수 없다 |
| 회사 정보 | 거래명세서의 공급자 정보는 환경변수(`ERP_COMPANY_NAME` 등)로 넣는다. 저장소에 실제 값을 넣지 않는다 |
