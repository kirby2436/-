# NEOTEC ENC 건설자재 ERP — 1차 버전 명세

현행 ERP "거푸집" 모듈의 앞단(프로젝트·구간 등록, 구간 BOM 업로드, 진행현황)을 웹으로 다시 만든다. 배경은 `docs/reference/현행-ERP-거푸집-모듈-파악.md` 참고.

## 1. 범위

포함:
1. 프로젝트·구간 등록 (수주정보, 단가, 구간, 도면/BOM 파일 포함)
2. 구간 BOM 엑셀 업로드와 성형품 소요량 집계
3. 프로젝트 진행현황 (구간별 Activity 일정과 실적), 홈 대시보드

제외 (2차 이후): 생산지시, 절단 길이 합산(Min/Max), 생산실적, 외주 발주·입고, 출하, Stirrup 재고, 견적, 세금계산서, 메신저·AI 연동.

## 2. 설계 원칙 (현행 불편을 없애는 방향)

- 조회 화면과 등록·수정 화면을 분리한다. 상세 화면은 읽기 전용이고 "수정" 버튼으로만 편집에 들어간다.
- 코드는 시스템이 자동 부여한다. 사용자는 코드 번호를 정하지 않는다.
- 거래처, 원청, 층, 품목 구성은 필요한 화면에서 바로 추가한다(다른 메뉴로 이동하지 않는다).
- 삭제와 덮어쓰기는 확인 단계를 거치고, 누가 무엇을 바꿨는지 기록한다.
- PC와 휴대폰 화면 모두에서 쓸 수 있어야 한다(반응형, 360px 폭에서 가로 스크롤 없음. 넓은 표는 표 영역 안에서만 스크롤).
- 화면 문구는 한국어.

## 3. 기술 구성

- Python 3.13, Django 6.x, SQLite(개발). 운영 DB 교체가 가능하도록 SQLite 전용 기능은 쓰지 않는다.
- 서버 렌더링 템플릿. 빌드 단계 없는 CSS 한 벌과 소량의 순수 JS. 외부 CDN 금지.
- 엑셀은 `openpyxl`.
- 모든 화면은 로그인 필요. 사용자 관리는 Django admin.
- 시간대 `Asia/Seoul`, 언어 `ko-kr`.

  projects/          프로젝트·구간 화면              (T2 소유)
  bom/               BOM 업로드 화면                 (T3 소유)

규칙: 모든 모델과 마이그레이션은 `core`에만 둔다. T2~T5는 `core`의 모델·마이그레이션·`config`·`base.html`을 수정하지 않는다. 모델 변경이 필요하면 수정하지 말고 보고서에 적는다.

### 프로젝트 코드

`P` + 계약일(없으면 등록일)의 `YYMM` + `-` + 그 달의 3자리 일련번호. 예: `P2311-001`. 저장 시 자동 생성하고 이후 바꾸지 않는다.

### ActivityType 초기값 (현행 기초코드 그대로)

| code | name | lead_days | 기준 | mark | actual_source |
|---|---|---|---|---|---|
| P100 | 도면/BOM | -21 | 출고 | D | BOM_UPLOAD |
| P200 | Stirrup발주 | -14 | 출고 | SO | MANUAL |
| P300 | Stirrup입고 | -3 | ASS'Y (P700) | SP | MANUAL |
| P400 | COIL발주 | -5 | 성형생산 (P600) | CO | MANUAL |
| P500 | COIL입고 | -1 | 성형생산 (P600) | CP | MANUAL |
| P600 | 성형생산 | -7 | 출고 | M | MANUAL |
| P700 | ASS'Y | -2 | 출고 | A | MANUAL |

## 5. 공통 서비스 (`core/services/`, T1 구현)

- `schedule.add_business_days(date, n)`: 토·일을 건너뛰는 영업일 계산(n은 음수 가능). 공휴일은 1차에서 반영하지 않는다.
- `schedule.sync_section_activities(section)`: 구간의 모든 ActivityType에 대해 SectionActivity를 만들거나 `planned_date`를 다시 계산한다. 출고 기준일은 `confirmed_ship_date`가 있으면 그것, 없으면 `planned_ship_date`. 다른 Activity 기준이면 그 Activity의 계획일에 `lead_days`를 더한다. `is_completed`이고 `confirmed_ship_date`가 있으면 P900 실적일을 그 날짜로 채우고, 아니면 P900 실적일을 비운다. 다른 실적일은 건드리지 않는다. Section 저장 시 자동 호출(post_save).
- `schedule.set_actual(section, code, date_or_None, user)`: 실적일 설정/해제 + 감사 기록.
- `schedule.activity_state(section_activity, today)`: `done`(실적 있음) / `late`(계획일 < 오늘, 실적 없음) / `soon`(오늘부터 영업일 3일 이내) / `planned`.
- `audit.log(user, action, obj, changes=None)`.
- `codes.next_project_code(base_date)`.

## 6. 화면 명세

### 6.1 프로젝트·구간 (T2, `projects/`)

- **목록** `projects:list`: 코드·이름 검색, 상태·구분·매출처 필터, 페이지 나눔. 열: 코드, 이름, 구분, 상태, 매출처, 원청, 기간, 수주금액, 구간 수. 휴대폰에서는 카드형.
- **상세** `projects:detail`: 읽기 전용. 기본정보, 수주정보, 품목 단가, 구간, 파일을 구역별로 표시. 각 구역에 "수정" 버튼. 구간 행에서 BOM(`bom:section`)과 일정(`schedule:section`)으로 이동.
- **신규** `projects:create`, **기본정보 수정** `projects:edit`: 코드 입력란 없음(자동). 매출처·원청 선택 옆 "새로 추가"로 그 자리에서 거래처 추가.
- **수주정보 / 품목 단가 / 구간 편집**: 각각 별도 편집 화면에서 여러 행을 한 번에 추가·수정·삭제. 구간 편집에서 층과 외주제작처를 그 자리에서 추가.
- **파일**: 순번 자동, 배포일자 기본값 오늘, 구간 선택, 파일 선택(끌어다 놓기 지원)으로 등록. 삭제는 확인 후.
- 규칙: BOM이 있는 구간은 삭제 불가(안내 문구 표시). 프로젝트 삭제 기능은 만들지 않는다(상태를 강제완료로 변경). 모든 생성·수정·삭제는 AuditLog에 남긴다.

### 6.2 구간 BOM (T3, `bom/`)

- **구간 선택** `bom:index`: 프로젝트·구간 검색 목록, 구간별 BOM 건수와 품목 미등록 건수 표시.
- **구간 BOM** `bom:section`: BOM 표(Ass Mark, Profile, Length, 수량, FINISH, LOCATION, 구성 상태), 합계, "엑셀 업로드" 버튼, 성형품 소요량 요약.
- **업로드** `bom:upload`:
  1. `.xlsx` 파일 선택 또는 엑셀에서 복사한 표 붙여넣기(탭 구분 텍스트).
  2. 머리글 `Ass Mark, Profile, Length(mm), Q'ty, FINISH, LOCATION`을 대소문자·공백·괄호 무시하고 인식. 머리글이 첫 행이 아니어도 찾는다.
  3. 미리보기: 행별 오류(Ass Mark 없음, 길이·수량이 숫자가 아님 또는 0 이하)는 저장을 막는다. 파일 내 또는 기존 BOM과 Ass Mark가 겹치면 경고만 표시.
  4. 방식 선택: "새로 등록"(구간의 기존 BOM을 모두 지우고 등록, 기존 건수 표시 후 확인) 또는 "추가 등록".
  5. 저장 시 Profile 이름으로 `Product`를 찾아 연결. 없으면 `product`를 비워 "품목 미등록"으로 저장(저장은 막지 않는다).
  6. 구간의 첫 업로드 저장 시 P100(도면/BOM) 실적일을 그 날짜로 설정. 구간 BOM이 모두 없어지면 해제.
- **누락 품목 정리** `bom:resolve`: 구간에서 품목 미등록이거나 구성이 없는 Profile 목록. 각 Profile에 대해 한 화면에서 COIL 두께(하판/측판), 하판 1~3과 측판 1~3의 규격·수량·비규격 여부를 입력해 `Product`와 구성을 만든다. 규격(`FormedPart`)은 입력 중 바로 추가. 저장하면 같은 Profile의 모든 BomItem에 연결.
- **성형품 소요량 요약**: 규격별(구분, 규격, 두께)로 수량 = Σ(BOM 수량 × 구성 수량), 총 길이(mm) = Σ(길이 × BOM 수량 × 구성 수량). 구성이 없는 품목은 제외하고 제외 건수를 알린다.
- BOM 개별 행 삭제(확인 후)와 비고 수정 가능.

### 6.3 진행현황 (T4, `schedule/`)

- **홈** `schedule:home` (`/`): 진행 중 프로젝트 수, 이번 주 출고 예정 구간, 지연 Activity 목록(구간·단계·계획일·지연 일수), 최근 변경 기록 10건.
- **진행현황판** `schedule:board`: 필터(점검기간: 계획일 기준 시작~종료, 프로젝트, 상태, 담당자, "지연만"). 행 = 구간(프로젝트명, 구간, 층, 출고예정/확정일), 열 = 9개 Activity. 칸에 계획일과 실적일, 상태 색(완료/지연/임박/예정)과 범례. 휴대폰에서는 구간별 카드.
- **구간 일정** `schedule:section`: 9개 Activity의 계획일, 실적일, 상태. 수기 단계는 실적일 입력·해제 가능, 자동 단계(P100, P900)는 읽기 전용이고 무엇으로 반영되는지 안내.
- 색만으로 상태를 구분하지 않는다(문구나 기호 병기).

## 7. 품질 기준 (모든 태스크 공통)

- `python manage.py check` 통과, `python manage.py test` 전부 통과.
- 각 앱에 테스트: 서비스 로직 단위 테스트, 주요 화면의 GET 200과 POST 성공·실패 경로, 비로그인 접근 시 로그인으로 이동.
- 폼 오류는 한국어로 해당 입력란 옆에 표시.
- 주석과 문서에 개인 이름이나 실제 거래처 이름을 넣지 않는다.
