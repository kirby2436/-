# 현행 ERP "거푸집" 모듈 파악

사용자가 제공한 현행 ERP 매뉴얼(거푸집 모듈, rev.00, 2023-11-30 제정, 57쪽)을 읽고 정리한 메모입니다. "불편할 것으로 보이는 점"은 매뉴얼만 보고 추정한 것이며, 실제 사용자 의견으로 확인해야 합니다.

## 1. 다루는 업무

- 제품은 **무해체 보거푸집(보데크)** 입니다. COIL(강판)을 성형해 하판과 측판을 만들고, 외주 제작처에서 Stirrup(철근)과 조립(ASS'Y)해 완성품으로 만든 뒤 현장 구간별로 출하합니다.
- 관리 단위는 **프로젝트(현장) → 구간(구역·층) → 부재(Ass Mark)** 입니다.
- 프로그램은 PC 설치형 화면입니다. 상단 메뉴는 거푸집, 구매/자재, 품질, 설비, 인사, 총무, 회계, 결산, 원가, 목표원가 등으로, 제조업 ERP의 구조에 "거푸집" 모듈을 추가한 형태입니다.

## 2. 메뉴와 흐름

| 순서 | 메뉴 | 화면 코드 | 하는 일 |
|---|---|---|---|
| 1 | 프로젝트 등록 | CTP100 | 프로젝트, 매출처, 원청, 수주정보, 품목 단가, 구간 정보, 외주 제작처, 도면·BOM 파일 등록 |
| 2 | 프로젝트 Activity 및 기본일정 등록 | CTP110 | 구간별 출고예정일 기준으로 단계별 계획일 자동 설정, 실적일 반영 |
| 3 | 프로젝트 진행현황 | CTP120 | 프로젝트·구간별 계획 대비 실적 모니터링 |
| 4 | 프로젝트구간 BOM 등록 | CTB100 | 설계팀 엑셀 BOM 업로드, 성형품 소요량 산출, 생산지시 대기 등록 |
| 5 | 프로젝트구간 BOM 생산지시 등록(현장별) | CTB150 | 지시일자, 설비, 규격을 골라 성형 생산지시 |
| 6 | 생산지시현황 및 생산실적 등록 | PPC160 | 지시 확인, 라벨 출력(출력 시 실적 기본정보 일괄 등록) |
| 7 | 생산실적 완성 | PPC165 | 작업시간, 불량, 비가동, 작업자 등록 |
| 8 | 완성품 생산지시 등록(발주서) | MMB140 | 외주 조립 발주, 발주서·불출명세서·라벨 출력 |
| 9 | 완성품 외주발주 생산입고 등록 | LEA130 | 외주 완성품 입고 처리 |
| 10 | 완성품 생산실적(입고) 현황 | LEA131 | 입고 현황 조회 |
| 11 | 완성품 출하등록 | LEB170 | 완성품 출하 |
| 12 | Stirrup 입고등록 / 입고현황 출고처리 / 출고등록 / 수불현황 | CTL100 / CTL105 / CTL110 / CTL200 | Stirrup 입고, 출고, 재고 |
| 13 | 기준정보: 보데크 구성 등록, 외주제작처 등록 | DMA170, BCV151 | 완제품별 하판·측판 구성, 외주처와 라벨 색상 |

일정 단계는 도면/BOM, Stirrup 발주, Stirrup 입고, COIL 발주, COIL 입고, 성형생산, ASS'Y, PACKING, 출고입니다.

## 3. 업무 규칙 (새 ERP에서도 유지해야 할 것)

- **BOM 항목**: Ass Mark(부재번호), Profile(제품명), Length, 수량, FINISH, LOCATION.
- **완제품 구성**: 하판 1~3, 측판 1~3의 규격과 수량, COIL 두께, 중량. 도면 규격과 다르면 "비규격" 표시.
- **절단 길이 합산**: 제품 길이가 Min(예: 3500)보다 짧으면 다른 제품과 이어서 생산하고, 합산 길이는 Max를 넘지 않게 합니다. 절단 손실은 (제품 수 − 1) × 2mm입니다.
- **프로젝트 상태**: 수주, 진행, 완료, 강제완료.
- **수불**: 불출명세서 실행 시 성형품이 외주 제작처 창고로 이동합니다. 출하 시 거래처 창고가 있어야 합니다.
- **자동 계산**: 작업시간(분), 불량 중량, 비가동 공수, Stirrup 중량.

## 4. 불편할 것으로 보이는 점 (추정)

1. **조회와 등록이 한 화면**: "신규"를 누르지 않고 입력하면 기존 프로젝트가 수정될 수 있다고 매뉴얼이 경고합니다. Stirrup 입고도 같습니다.
2. **코드 수동 관리**: 프로젝트 코드는 규칙 없이 직접 입력합니다. 원청사와 층 코드는 우클릭으로 기초코드 창을 열어 중복되지 않는 3자리 숫자를 직접 정해야 합니다.
3. **선행 등록이 많음**: 거래처, 원청, 층, 외주 제작처, 품목, 완제품 구성, 거래처 창고가 먼저 등록되어 있지 않으면 다음 단계가 막힙니다. 일부는 기획관리팀에 문의해야 합니다.
4. **BOM 업로드가 수작업**: 엑셀에서 범위를 복사해 화면에 붙여넣고, 빨갛게 표시된 누락 정보를 건별로 채웁니다.
5. **일정 실적 일부 수기 입력**: Stirrup 발주, COIL 발주, COIL 입고, PACKING 실적일은 담당자가 직접 넣습니다.
6. **취소가 행 삭제 방식**: 발주, 입고, 출하 취소를 조회 후 행 삭제로 하며, 날짜를 직접 확인해야 합니다.
7. **제조업 용어와 화면**: 생산지시, 수불, 불출, 공수 같은 용어와 4~6분할 화면이 현장·영업 담당자에게 익숙하지 않을 수 있습니다.
8. **단계가 많음**: 한 구간을 출하하기까지 10개 안팎의 화면을 순서대로 거칩니다.
9. **모바일 사용 불가로 보임**: 공장과 현장에서 바로 입력하기 어렵습니다.
10. **매뉴얼 자체의 불일치**: 여러 쪽의 상단 구분명이 실제 메뉴와 다르고, 메뉴에 있는 "Stirrup 출고등록"은 목차에 없습니다.

## 5. 이 매뉴얼에 없는 것

견적, 계약, 수금, 세금계산서, 구매 발주(COIL, Stirrup), 원가, 현장 시공 관리는 이 모듈 매뉴얼에 없습니다. 다른 모듈에 있는지는 확인이 필요합니다.
