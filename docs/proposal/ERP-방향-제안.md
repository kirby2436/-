# 1. 요약

- ERP를 메뉴 중심이 아니라 **현장 한 건이 영업 → 설계 → 공사관리 → 생산 → 정산으로 흘러가는 흐름** 중심으로 만든다.
- 다음에 만들 것은 **입고 일정(공사관리와 생산 사이)** 을 권한다. 매일 여러 부서가 함께 쓰고, 지금 구글 캘린더와 이중으로 관리될 부분이기 때문이다.
- 구글 캘린더는 **없애지 않고, ERP에 입력한 일정이 구글 캘린더에 자동으로 표시되게** 한다. 일정의 원본은 ERP 한 곳으로 둔다.
- 회계는 마지막에 다룬다. 그때까지는 청구·수금 자료를 엑셀로 내보내 본사에 전달한다.
- 이 제안은 설명해 주신 부서 업무와 현행 ERP 매뉴얼을 근거로 했다. 회사 양식과 자료 폴더는 아직 읽지 못했으므로, 양식을 확인한 뒤 세부 항목을 보완한다.

# 2. 현재 상태

| 구분 | 내용 |
|---|---|
| 1차 버전(완료) | 프로젝트·구간 등록, 구간 BOM 엑셀 업로드, 구간별 진행현황 |
| 현행 ERP | 제조업용 구조에 거푸집 메뉴를 붙인 형태. 생산 쪽 메뉴만 있고 영업, 공사관리 업무는 없음 |
| 실제 업무 도구 | 회사 서버의 현장 폴더(도면), 엑셀·한글 양식(견적서, 수주보고서, 청구서, 정산보고서), 구글 캘린더(제작·입고 일정), 전화와 메일 |

현행 ERP가 잘 안 쓰이는 이유는 화면이 불편한 것만이 아니라, 영업과 공사관리의 실제 업무가 ERP 밖에 있기 때문으로 보인다.

# 3. 설계 방향

## 3.1 현장 한 건의 흐름

| 단계 | 담당 | ERP에서 일어나는 일 |
|---|---|---|
| 견적 접수 | 영업 | 접수 등록(거래처, 현장, 연락처, 접수 경로) |
| 도면 수취 | 영업 | 현장 폴더에 도면 등록 |
| 물량 산출 | 설계 | 영업의 의뢰가 설계의 할 일로 생성, 산출 결과 등록 |
| 견적 제출 | 영업 | 산출 물량으로 견적서 작성·출력, 회신 대기 알림 |
| 계약·수주 | 영업 | 계약서 등록, 수주보고서 작성과 결재 |
| 실시 설계 | 설계 | 구간별 도면·SHOP·BOM 등록(1차 버전 기능) |
| 입고 일정 | 공사관리, 생산 | 현장과 협의한 입고 요청 → 생산 확정 → 달력 표시 |
| 생산·출하 | 생산 | 성형·완제품 실적, Stirrup 입출고, 출하와 배차 |
| 청구·수금 | 공사관리 | 월 마감 기준 청구서 작성, 수금 기록, 미수금 조회 |
| 정산 | 영업 | 정산보고서 작성과 제출 |

앞 단계에서 입력한 내용이 뒤 단계 문서에 자동으로 채워지게 한다. 예를 들어 출하 실적이 월 청구서로, 청구와 수금이 정산보고서로 이어진다.

## 3.2 원칙

1. **부서별 첫 화면**: 로그인하면 자기 부서의 할 일과 현장이 먼저 보인다.
2. **한 번만 입력**: 거래처, 현장, 물량, 단가는 한 번 입력하고 견적서, 수주보고서, 청구서, 정산보고서에 다시 쓴다.
3. **회사 양식 그대로 출력**: 지금 쓰는 양식 모양으로 엑셀이나 PDF를 내보낸다.
4. **부서 간 요청은 할 일로**: 물량 산출 의뢰, 입고 요청처럼 전화로 하던 요청을 기록으로 남기고 담당자에게 알린다.
5. **현장에서 휴대폰으로**: 공사관리 담당자가 현장에서 일정 확인, 방문 기록, AS 접수를 할 수 있어야 한다.
6. **작게 만들어 바로 쓴다**: 한 번에 한 부서의 한 가지 업무를 만들어 배포하고, 불편한 점을 받아 고친다.

# 4. 부서별 제안 기능

## 4.1 영업

| 기능 | 내용 |
|---|---|
| 견적 접수 대장 | 전화·메일로 들어온 견적 요청을 등록하고 진행 상태(도면 대기, 산출 중, 견적 제출, 계약, 실주)를 추적 |
| 현장 폴더 | 현장별 도면과 문서를 등록. 회사 서버 폴더 대신 또는 서버 폴더와 연결 |
| 물량 산출 의뢰 | 버튼 한 번으로 설계에 의뢰. 설계의 할 일에 생성되고 완료되면 영업에 알림 |
| 견적서 작성 | 산출 물량과 단가로 견적서를 만들고 회사 양식으로 출력. 개정 이력 보관 |
| 회신 대기 알림 | 견적 제출 후 일정 기간 회신이 없으면 담당자 할 일로 자동 등록 |
| 계약·수주보고서 | 계약 정보를 등록하면 수주보고서가 자동 작성되고 결재선에 따라 승인 |
| 정산보고서 | 출하 실적, 청구, 수금 내역을 모아 정산보고서 초안을 자동 작성 |

## 4.2 설계

| 기능 | 내용 |
|---|---|
| 의뢰함 | 물량 산출과 실시 설계 요청을 한 목록에서 관리(요청일, 기한, 상태) |
| 산출 결과 등록 | 물량 도면과 산출 물량을 현장에 등록. 영업의 견적서로 이어짐 |
| 구간 도면·SHOP·BOM | 1차 버전 기능. 도면 개정 이력과 배포 기록 추가 |
| 현장 협의 기록 | 도면 수정 요청과 통화 내용을 현장별로 기록 |

## 4.3 공사관리

| 기능 | 내용 |
|---|---|
| 입고 요청과 확정 | 현장과 협의한 입고일·구간·물량을 등록하면 생산이 확정하거나 조정. 변경 이력 보관 |
| 입고 달력 | 현장별, 제작장별 입고 일정을 달력으로 조회. 구글 캘린더에 자동 표시 |
| Stirrup 일정 | Stirrup의 입고 예정일과 입고 장소(제작장)를 구간별로 관리 |
| 월 청구서 | 마감일(25일 또는 말일) 기준으로 그 달 출하 실적과 계약 단가로 청구서 초안 작성 |
| 수금 관리 | 청구 대비 수금 기록, 현장별 미수금 조회 |
| AS·자재 문제 접수 | 접수, 조치 내용, 사진, 완료 여부를 현장별로 기록 |
| 현장 방문 기록 | 방문일, 만난 사람, 협의 내용을 휴대폰으로 기록 |

## 4.4 생산

| 기능 | 내용 |
|---|---|
| 생산 계획과 실적 | 확정된 입고 일정에서 역산한 생산 계획, 성형 실적과 완제품 실적 등록 |
| Stirrup 입출고 | 입고, 출고, 재고 |
| 출하와 배차 | 출하 등록, 운송사 차량 요청 기록, 거래명세서 출력 |
| 제작장별 현황 | 사내·사외 제작장별 물량과 일정 |

현행 ERP의 생산 메뉴 중 실제로 쓰는 것만 옮긴다. 어떤 화면을 실제로 쓰는지 생산 담당자 확인이 필요하다.

## 4.5 회계

마지막에 다룬다. 본사 회계 시스템과 직접 연결할지, 자료만 넘길지는 그때 정한다. 그 전까지는 청구와 수금 내역을 엑셀로 내보낸다.

# 5. 구글 캘린더 처리 방안

## 5.1 선택지 비교

| 방안 | 장점 | 단점 |
|---|---|---|
| A. 구글 캘린더를 계속 원본으로 사용, ERP는 읽기만 | 지금 방식 그대로 | 일정이 자유 입력이라 현장·구간·물량과 연결되지 않음. 청구, 생산 계획에 쓸 수 없음. 이중 입력 발생 |
| B. ERP 달력으로 완전히 대체 | 원본이 한 곳 | 직원들이 익숙한 휴대폰 캘린더와 알림을 잃음. 도입 저항이 큼 |
| C. ERP가 원본, 구글 캘린더에 자동 표시(권장) | 일정이 현장·구간·물량과 연결됨. 휴대폰 캘린더와 알림은 그대로 사용 | 구글 캘린더에 직접 입력하던 습관을 바꿔야 함 |
| D. 양방향 동기화 | 어느 쪽에서든 수정 가능 | 구글에서 고친 자유 문구를 ERP의 구조화된 항목으로 되돌리기 어렵고 충돌 처리가 복잡함 |

## 5.2 권장: 방안 C

- 입고 일정은 "언제"만이 아니라 현장, 구간, 물량, 제작장, 차량이 함께 붙는 자료다. 이 자료가 출하 실적, 월 청구서, 정산보고서로 이어지므로 원본은 ERP에 있어야 한다.
- 구글 캘린더는 직원들이 이미 휴대폰으로 보는 화면이므로 보기용으로 유지한다.
- 현재 캘린더가 제작장별로 나뉘어 있고 통합 일정 캘린더가 따로 있다. 이 구조를 그대로 살려, ERP의 일정이 해당 제작장 캘린더에 자동으로 올라가게 한다.

## 5.3 전환 순서

1. ERP에 입고 요청·확정과 달력 화면을 만든다.
2. ERP 일정을 구글 캘린더에 자동으로 올린다. 일정 제목 형식은 지금 쓰는 표기를 따른다.
3. 일정 기간 병행한 뒤, 구글 캘린더 직접 입력을 중지한다. 개인 메모성 일정은 구글 캘린더에 계속 써도 된다.

# 6. 개발 순서 제안

| 순서 | 범위 | 이유 |
|---|---|---|
| 완료 | 프로젝트·구간, BOM 업로드, 진행현황 | |
| 2차 | 입고 요청·확정, 입고 달력, 구글 캘린더 표시, Stirrup 일정 | 공사관리·설계·생산이 매일 함께 쓰는 부분. 캘린더 이중 관리 해소 |
| 3차 | 견적 접수, 물량 산출 의뢰, 견적서, 수주보고서와 결재 | 영업 업무를 ERP 안으로. 양식 확인 필요 |
| 4차 | 출하·배차, 월 청구서, 수금, AS 접수 | 출하 실적이 있어야 청구서를 자동 작성할 수 있음 |
| 5차 | 정산보고서, 생산 실적 상세, Stirrup 재고 | 앞 단계 자료가 쌓인 뒤 가능 |
| 6차 | 회계 연계 | 본사와 협의 후 결정 |

# 7. 확인이 필요한 사항

1. **회사 양식과 자료**: 견적서, 수주보고서, 청구서, 정산보고서 양식을 봐야 항목을 확정할 수 있다.
2. **캘린더 일정의 실제 표기**: 일정 제목과 내용에 무엇을 어떻게 적는지 예시가 필요하다.
3. **결재선**: 수주보고서와 정산보고서를 누가 결재하는지.
4. **회사 서버**: 현장 폴더를 ERP로 옮길지, 서버를 그대로 두고 ERP에서 경로만 연결할지.
5. **설치 위치**: 현장에서 휴대폰으로 쓰려면 인터넷에서 접속되는 서버가 필요하다.
