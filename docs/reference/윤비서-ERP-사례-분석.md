NEOTEC ENC ERP를 설계할 때 참고할 기능 메모입니다.

## 사례 개요

- 윤자동(윤용승 대표)은 업무 자동화 교육·에이전시 회사입니다. 홈페이지: https://www.yunjadong.com/
- Claude Code로 사내 ERP와 AI 비서 "윤비서"를 직접 만들었습니다.
- 노션 같은 기성 SaaS는 데이터가 늘면서 속도, 모바일 사용성, 관계형 데이터 관리에 한계가 와서 자체 ERP로 옮겼습니다.
- 핵심은 AI 도구 도입이 아니라 **데이터를 한곳에 모으는 것**입니다. 프로젝트, 고객, 미팅 기록, 매출, 세금계산서, 일정, 업무 할당이 한 시스템에 있습니다.

## 구조 (4개 층)

| 층 | 내용 |
|---|---|
| 입력 | 미팅 녹음, 명함, Gmail, Google Drive, 결제, 입금 알림, GitHub, 직원 요청 |
| 데이터 | 고객, 프로젝트, 매출, 문서, 일정, 업무, 리포트 |
| 처리 | Claude Code, OCR, API, Zapier, Slack 앱, 필요 시 MCP |
| 액션 | 할 일 배정, 세금계산서 초안, 일정 등록, 리포트, 고객 후속 연락 |

가장 중요한 층은 데이터 층입니다. 입력 도구와 AI 모델은 바뀔 수 있지만 고객·프로젝트·매출·업무의 정의가 흔들리면 자동화 전체가 흔들립니다.

## 확인된 기능

- **미팅 기록 자동 정리**: 녹음에서 요약, 결정사항, 할 일을 뽑아 고객과 프로젝트에 연결합니다.
- **명함 인식**: 명함을 OCR로 읽어 고객 정보로 넣습니다.
- **매출과 세금계산서 관리**: 결제·입금 알림을 받아 매출에 반영하고, 세금계산서 발행 상태를 추적하며 초안을 만듭니다.
- **업무 할당**: 결정사항이나 요청에서 할 일을 만들어 담당자에게 배정합니다.
- **Slack 자연어 비서**: 직원이 Slack에서 말로 요청하면 비서가 일정 등록 같은 다음 액션을 처리합니다. 별도 화면에 들어갈 필요가 없습니다.
- **리포트**: 일일 요약과 누락 점검을 만듭니다.

## 최소 데이터 모델 (정리 글의 제안)

| 객체 | 최소 필드 | 이어지는 액션 |
|---|---|---|
| 고객 | 이름, 회사, 담당자, 상태 | 후속 연락 생성 |
| 프로젝트 | 고객, 계약상태, 담당자, 마감일 | 업무 템플릿 생성 |
| 미팅 | 고객, 요약, 결정사항, 녹취 링크 | 할 일 추출 |
| 매출 | 고객, 결제일, 금액, 세금계산서 상태 | 발행 확인 |

## 설계 원칙 (정리 글의 권고)

- **AI 요청은 바로 실행하지 않습니다.** 요청을 "제안된 액션"으로 저장하고 담당자가 승인하면 실행합니다.
- **위험도에 따라 나눕니다.** 조회, 요약, 초안 생성은 낮은 위험입니다. 외부 메일 발송, 세금계산서 발행, 결제 취소, 계약서 수정은 승인을 거칩니다.
- **로그를 첫 버전부터 남깁니다.** 누가 요청했는지, 무엇이 입력됐는지, AI가 무엇을 제안했는지, 누가 승인했는지, 외부 API가 무엇을 실행했는지 기록합니다.
- **요약과 원본을 함께 둡니다.** 녹취, 메일, 세금계산서 원문 링크를 남깁니다.
- **첫 버전은 작게 만듭니다.** 반복 업무 하나를 중앙 DB에 붙이는 것부터 시작합니다.
- **도입 순서**: 객체 정의, 입력 자동화 한 가지, 메신저에서 조회만 허용, 승인 대기 액션 순으로 넓힙니다.

## NEOTEC ENC ERP에 적용할 때의 대응

| 윤비서 | 건설자재 ERP에서의 대응 (제안) |
|---|---|
| 고객 | 거래처(발주처, 시공사, 공급사) |
| 프로젝트 | 현장 또는 수주 건 |
| 미팅 기록 | 현장 협의, 견적 협의 기록 |
| 매출·세금계산서 | 납품, 기성 청구, 세금계산서 상태 |
| 업무 할당 | 견적, 발주, 출하, 수금 담당 업무 |
| Slack 비서 | 사내 메신저나 ERP 안의 대화창에서 재고, 납기, 미수금 조회 |

이 대응은 제안이며, 실제 업무 흐름과 기존 ERP의 불편 사항을 받은 뒤 확정합니다.
