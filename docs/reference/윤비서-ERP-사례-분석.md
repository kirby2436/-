## 1. 도입 배경

윤자동은 대표 포함 9명 규모의 자동화 에이전시·교육 회사입니다 [01:44]. 처음에는 노션으로 사내 DB를 운영했지만 다음 한계로 자체 ERP로 옮겼습니다 [04:30].

- **속도 저하**: 프로젝트와 뷰가 늘수록 로딩이 느려졌습니다 [07:29].
- **모바일 불편**: 외근 중 조회와 입력이 어려웠습니다 [07:38].
- **관계형 구조의 진입 장벽**: 테이블 관계가 복잡해져 직원들이 제대로 쓰지 못했습니다 [07:47].
- **맞춤화 한계와 비용**: 기성 제품에 업무를 맞추는 대신 AI 코딩으로 회사에 맞춘 웹 ERP를 만들고 구독료를 줄였습니다 [04:50].

취지는 "임원의 전담 비서 역할을 고정비 없이 AI로 구현한다"입니다 [05:58].

## 2. 기능 전체 목록

메뉴 2개로 시작해 약 20여 개로 늘었습니다 [10:08].

| 영역 | 기능 | 연동 도구 | 효과 |
|---|---|---|---|
| 영업·프로젝트 | 프로젝트 및 고객 관리 | 자체 웹 DB, 마스킹 토글 | 120건 이상 프로젝트 중앙 관리 |
| 영업·프로젝트 | 미팅 녹음 자동 적재 | PLAUD 녹음기, Zapier | 700건 이상 회의록 자동 수집 |
| 영업·프로젝트 | 견적서 자동 발행 | 회의록·고객 DB | 표준 양식 견적서 원클릭 발행 |
| 협업·일정 | 팀 할 일 관리 | 칸반보드, Slack 알림 | 담당자 할당, 마감 반복 알림 |
| 협업·일정 | 일정 관리 | Google Calendar 양방향 | 아침 7시 일정 브리핑 |
| 협업·일정 | 파일·문서 관리 | Google Drive API | 별도 저장소 비용 없음, 드라이브 권한 사용 |
| 커뮤니케이션 | 명함 OCR과 주소록 | Gemini OCR, Google Contacts API | 월 50원 미만, 휴대폰 연락처 자동 등록 |
| 커뮤니케이션 | 전 직원 메일 통합 | Gmail | 프로젝트 맥락에서 고객 소통 이력 검색 |
| 재무·총무 | 매출과 실시간 입금 | 아임웹 동기화, 은행 푸시 알림 캐치 | 결제·수주 매출·실입금 자동 집계 |
| 재무·총무 | 세금계산서 발행과 지출 | 홈택스 API, 영수증 OCR(예정) | 담당자가 직접 발행 |
| 재무·총무 | 인사·총무 발급 | Claude Code | 재직증명서 셀프 발급 |
| AI 에이전트 | 개발 일일 보고 자동화 | GitHub 푸시 내역 분석 | 매일 저녁 6시 자동 보고 |
| AI 에이전트 | Slack 자연어 비서 | Slack 앱, 권한 분리 | 비정형 일정 등록, 대화 중 DB 조회·기록 |
| AI 에이전트 | 윤자동 OS | Claude Code, Workspace CLI | 메일 분류·답장, 매출·실주 분석 |

### 2.1 영업, 고객, 프로젝트

1. **프로젝트·고객 통합 관리 (코어)**
   - 도입 2개월 만에 120건 이상이 쌓였고, 진행 중 35건의 진척도·담당자·히스토리를 전 직원이 봅니다 [07:09].
   - 고객사 기본 정보와 사업자등록증을 한곳에 두어 견적서나 세금계산서를 낼 때 다시 입력하지 않습니다 [10:33].
   - 외부 시연 때 민감 정보를 가리는 **개인정보 마스킹** 기능이 있습니다 [06:50].
2. **미팅 녹음 자동 수집**
   - 전 직원에게 PLAUD 녹음기를 지급해 150일간 700건 이상을 녹음했습니다 [08:13].
   - 녹음이 끝나면 Zapier가 ERP로 자동 전송·적재합니다 [08:40].
   - 회의록이 견적서 작성, 후속 할 일, 계약 후 프로젝트 생성의 출발점이 됩니다 [09:00].
3. **견적서 자동 발행과 수주 연계**
   - 미팅 기록과 고객 DB로 표준 양식 견적서를 ERP 안에서 발행합니다 [09:10].
   - 계약이 성사되면 프로젝트 관리로 이어지고 후속 업무가 생성됩니다 [09:18].

### 2.2 협업, 일정, 문서

4. **칸반보드 할 일 관리와 Slack 알림**
   - 직원 간 업무 할당과 진행 추적을 칸반보드로 합니다 [09:18].
   - 웹 푸시나 모바일 앱은 과한 사양으로 보고, 알림과 소통은 Slack에 맡겼습니다 [12:27].
   - 할 일에 담당자를 지정하면 Slack 알림이 가고, 그 스레드에서 논의합니다 [12:09].
   - **자동 팔로업**: 견적 발송 후 회신이 없으면 일주일 뒤 할 일로 자동 등록됩니다. 마감 30분 전에 알리고, 마감이 지나면 완료 처리할 때까지 반복 알림을 보냅니다 [37:41].
5. **Google Calendar 양방향 동기화**
   - 어느 쪽에서 일정을 바꿔도 실시간 반영됩니다 [15:30].
   - 주간·월간·일간 뷰와 단축키(W, M, D)를 Google Calendar와 같게 만들었습니다 [15:41].
   - 매일 아침 7시에 그날 일정을 브리핑합니다 [35:50].
6. **Google Drive 기반 파일 관리**
   - 대용량 파일을 별도 저장소(S3)에 두지 않고 Drive API를 연동했습니다 [13:21].
   - ERP의 프로젝트 폴더가 실제 Drive 폴더와 1:1로 연결되고, ERP 안에서 바로 열람하거나 시트를 편집합니다 [13:02].
   - 외부 공유는 Drive의 초대·권한 기능을 그대로 씁니다 [13:52].
7. **명함 OCR과 주소록**
   - 명함을 촬영하면 Gemini OCR이 정보를 추출합니다. 건당 0.1원 미만입니다 [17:18].
   - 사내 공용 주소록에 저장되고, Google Contacts API로 촬영자의 휴대폰 주소록에도 등록됩니다 [17:34].
8. **전 직원 업무용 Gmail 통합**
   - 프로젝트를 보다가 메일을 찾으러 화면을 옮기는 불편을 없애려고 만들었습니다 [18:08].
   - 직원 동의를 받아 각자의 업무 계정을 연동해, 조직 전체의 대외 소통 이력을 ERP에서 검색합니다 [18:29].

### 2.3 재무, 매출, 세무, 인사·총무

9. **실시간 매출·입금 추적**
   - 아임웹 홈페이지 결제 내역을 버튼 한 번으로 동기화합니다 [19:31].
   - 프로젝트별 수주 매출이 온라인 결제 매출과 함께 집계됩니다 [19:50].
   - 은행 앱의 입금 푸시 알림을 감지해 ERP API로 보내는 방식으로 입금을 자동 기록합니다 [20:11].
10. **홈택스 세금계산서 발행과 지출 관리**
    - 홈택스 API로 ERP 안에서 세금계산서를 발행합니다 [21:45]. 공급자와 고객사 정보가 DB에서 채워지고, 담당 직원이 확인 후 발행 요청을 누릅니다 [22:17].
    - 법인카드와 고정비를 관리하는 매입·지출 모듈은 개발 중입니다 [20:30]. 영수증 OCR 매칭과 세무사 자료 연계는 계획 단계입니다 [20:52].
11. **인사·총무 셀프 서비스**
    - 재직증명서 셀프 발급 메뉴를 Claude Code로 30초 만에 만들었습니다 [23:30].
    - 연차 신청과 잔여 일수, 급여 명세서 조회, 공지사항·게시판도 같은 방식으로 추가할 수 있습니다 [24:23].

### 2.4 AI 에이전트

12. **개발팀 일일 보고 자동화**: 매일 저녁 6시에 AI가 GitHub 푸시 내역을 분석해 일일 진행 보고를 작성·공유합니다 [36:00].
13. **Slack 자연어 비서**
    - 모든 Slack 채널에 "윤비서" 앱을 초대해 두었습니다 [25:24].
    - "내일부터 다음 주 금요일까지 월·수·금 오후 3~5시 일정 잡아줘" 같은 비정형 반복 일정을 등록합니다 [25:45].
    - 스레드 대화 중에 비서를 불러 그 자리에서 일정으로 등록합니다 [26:58].
    - 데이터 삭제 같은 민감한 명령은 사용자 최종 확인을 거칩니다 [26:08]. 급여나 경영진 전용 데이터는 사용자 ID와 채널별로 접근 권한을 나눕니다 [27:32].
14. **윤자동 OS (Claude Code 기반)**
    - 단순 조회·입력은 웹 ERP에서, 깊은 추론이 필요한 업무는 ERP DB·메일·드라이브를 연결한 Claude Code 환경에서 합니다 [28:12].
    - 메일을 "자동 분류 / 처리 / 답장 완료 / 조치 필요"로 태깅합니다 [29:26]. 의사결정이 필요한 건만 대표에게 묻고, 방향을 받으면 대표의 말투에 맞춰 초안을 쓰고 발송합니다 [30:15].
    - 경영 분석에도 씁니다: 업무 부하 점검 [31:00], 매출 분석과 성장 전략 [31:19], 미팅 녹취 기반 화법 교정 [31:34], 실주(수주 실패) 원인 분석 [31:51].

## 3. 구축 방법과 구조

### 3.1 불편한 것만 만든다

- **첫날에 코어만 출시**: "프로젝트 관리"와 "고객 관리" 2개 메뉴를 하루 만에 만들어 다음 날 전 직원에게 배포했습니다 [10:23]. 할 일·일정·메모는 기존 도구를 그대로 쓰게 했습니다 [10:40].
- **수요 기반 추가**: 실무에서 불편하다고 나온 부분만 하나씩 붙였습니다 [16:54]. 메뉴 하나에 보통 1시간 안팎이 걸렸고, 두 달 만에 20여 개가 됐습니다 [09:52].

### 3.2 구간별 연동 방식

| 구간 | 방식 | 이유 |
|---|---|---|
| 웹 ERP 내부 | 공식 API 직접 연동 | 전 직원이 쓰는 서비스는 안정적이어야 하므로 Drive, Contacts, Calendar, 홈택스를 API로 연결 [14:07] |
| Claude Code(윤자동 OS) | CLI(Google Workspace CLI)와 MCP | 에이전트가 메일·드라이브·ERP DB를 빠르게 가져와 분석 [14:17] |
| 외부 기기·모바일 | Zapier, 푸시 알림 캐치 | PLAUD는 Zapier로 중계, 은행 입금은 푸시 알림을 ERP API로 전송 [08:40] |

### 3.3 도구의 역할 분리 (4계층)

1. **자체 웹 ERP**: 현황 파악과 정형 데이터의 입력·수정·조회 [28:38]
2. **Slack**: 모바일 접근, 실시간 알림, 대화 중 자연어 입력과 간편 조회 [12:43]
3. **Google Workspace**: 저장소와 기본 인프라 [13:31]
4. **Claude Code**: 제안서, 장문 기획, 메일 분류·답장, 경영·영업 분석 [28:56]

### 3.4 두 가지 원칙

1. **데이터 중앙 집중**: 회의록, 메일, 매출, 일정 등 원천 데이터를 한 DB에 모아야 AI가 제대로 답합니다 [32:19].
2. **사람의 기억에 의존하지 않는 구조**: 녹음 적재, 일일 보고, 팔로업 알림처럼 시스템이 먼저 움직이게 만듭니다 [36:39].

## 4. NEOTEC ENC ERP에 적용할 때의 대응 (제안)

| 윤비서 | 건설자재 ERP에서의 대응 |
|---|---|
| 고객 | 거래처(발주처, 시공사, 공급사), 사업자등록증 포함 |
| 프로젝트 | 현장 또는 수주 건 |
| 미팅 녹음 적재 | 현장 협의, 견적 협의 기록 |
| 견적서 자동 발행 | 자재 견적서, 계약 후 수주 건으로 연결 |
| 칸반 할 일과 팔로업 알림 | 견적 회신, 발주, 출하, 수금 후속 관리 |
| 매출·입금·세금계산서 | 납품, 기성 청구, 입금 확인, 세금계산서 상태 |
| 인사·총무 셀프 서비스 | 재직증명서, 연차, 공지 |
| 메신저 자연어 비서 | 재고, 납기, 미수금 조회 |

이 대응은 제안입니다. 사용자가 이 중 어떤 기능을 원하는지와 기존 ERP의 불편 사항을 받은 뒤 확정합니다. 윤자동은 9명 규모의 서비스업이라 재고, 구매·발주, 출하 같은 건설자재 핵심 업무는 이 사례에 없습니다.
